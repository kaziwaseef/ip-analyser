# Use external tools with product data

Read [the research-system reference](../knowledge/research-systems.md) to choose a source. Confirm its current access and export rules before use.

Use official public sources and the user's existing tools first. Support copy/paste prompts, permitted exports, and available authorized connectors. New subscriptions, purchases, and custom integrations require the user's instruction. No provider-specific integration or subscription is implied by this policy.

1. Record the source, purpose, access method, account requirement, export limits, and intended data disclosure in the product's `tool-register.md`.
2. Prefer public product descriptions and minimal search concepts. Check whether combining details would disclose an unpublished invention.
3. For confidential information, use existing grants for the relevant service, product, and data. Record the actual authorization and reuse it for covered queries without repeated questions. Ask when a new disclosure is outside that scope. If no grant covers it, continue with public or redacted material.
4. Use an available permitted API, export, or manual interface. Do not assume that a public webpage permits bulk scraping or that one account permits all downstream uses.
5. Save the query, retrieval date, record identifiers, and permitted output. Record missing exports and source limitations.
6. Keep credentials outside the repository. Refer to an approved credential location by name without exposing its contents.

Classify each tool as `proposed`, `available`, `used`, or `unavailable`. A recommendation starts as `proposed`. Only an actual successful retrieval justifies `used`.

Do not create an account, buy a subscription, send a message, or start recurring monitoring based only on a source recommendation. Do not claim a watch is active until a service or scheduled process is actually configured and verified.

## Store ordinary documents in the workspace

The user accepts an intended private GitHub repository as the storage default. Preserve permitted original product evidence, supplier documents, contracts, and design files in the normal workspace paths. They may be versioned with the work. Do not require a separate restricted store or exclude ordinary product documents from Git merely because they are confidential. Keep credentials outside repository files.

Keep source export/retention limits with the evidence. Do not interpret private-repository storage as authorization to upload the material to another service. Do not create a remote repository, change visibility, or claim private hosting is configured merely from this storage preference; those actions need their actual task context.
